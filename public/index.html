Modeling Early Language Acquisition with Reinforcement Learning for Large Language Models

Banff Jiang · Colin Wang · Longhao Lin · Alex Warstadt

Code Charts Artifacts References

One-Screen Pitch

TeleSpeak tests whether child-like telegraphic speech can emerge from optimization under production constraints rather than from a hard-coded language bottleneck. We train a speaker with preference learning and a decaying pressure toward shorter utterances, then measure whether concise, meaning-preserving summaries become a stable strategy.

Why It Matters

The project connects BabyLM-style low-resource learning with a concrete cognitive hypothesis: if short utterances are useful under limited capacity, reinforcement learning should recover them without manually scripting them.

Target Reviewer

This site is written for technical readers evaluating model design, dataset rigor, and whether the results would justify the child-language claim.

Core Question Can length pressure alone induce telegraphic speech?

Problem Statement

Modern language models usually require much more data than human learners. BabyLM asks whether useful language behavior can be learned under strict token budgets, but it does not by itself explain why early child speech is often short, content-heavy, and structurally incomplete.

TeleSpeak treats this as an optimization question: if speaking is expensive, do short utterances emerge because they preserve enough meaning at lower production cost?

Target User and Stakeholder

The immediate audience is researchers and mentors interested in cognitively motivated language modeling, efficient learning, and reinforcement-learning-based sequence training. The broader stakeholder is anyone evaluating whether developmental language phenomena can be reproduced with transparent training objectives instead of hand-built rules.

Scope

We focus on a narrow, testable claim: whether a speaker optimized for semantic fidelity plus time-varying brevity pressure will move toward shorter outputs. This project is about emergent production behavior, not full child-language acquisition.

Out of Scope

We are not claiming that the current model captures syntax development, multimodal grounding, caregiver interaction, or developmental timelines. Those would require additional supervision, richer environments, and stronger behavioral evaluation than this capstone currently includes.

Approach Summary

The system pairs a generator with a learned evaluator. The generator proposes multiple candidate summaries for the same passage. The listener scores which candidate better preserves meaning, and DPO pushes the speaker toward the preferred candidate while a separate term rewards brevity early in training.

Data

Simple Wikipedia passages from the BabyLM-style setup, preprocessed to JSONL for training and analysis:

{"id": int, "source": "simplewiki", "passage": str}

Speaker

GPT-2 generates candidate summaries with stochastic decoding so the preference pipeline can compare concise and verbose alternatives.

Listener

RoBERTa-large provides semantic preference signals using BERTScore-style alignment, rewarding candidates that keep the source meaning intact.

Preference Filtering

Candidate pairs are diversity-filtered via 2-gram Jaccard similarity. Overly similar pairs are regenerated; persistent near-duplicates are discarded.

What We Built

Data preprocessing, candidate generation, listener scoring, DPO training code, and experiment tracking are all assembled in this repo as a single end-to-end training workflow.

What We Reused

We rely on BabyLM-style data framing, GPT-2 and RoBERTa checkpoints, BERTScore-style semantic comparison, and standard experiment logging tooling rather than building those foundations from scratch.

Training Objective

We combine DPO preference logits with a decaying length advantage term:

logits = beta * pref_logits + alpha(t) * len_adv
L = -log(sigmoid(logits))

pref_logits = (log pi_theta(y_c|x) - log pi_theta(y_r|x))
            - (log pi_ref(y_c|x)   - log pi_ref(y_r|x))

len_adv = (len_r - len_c) / (len_r + len_c + epsilon)
alpha(t) = alpha_0 * exp(-k * t)

This design enforces short outputs early, then gradually prioritizes semantic preference learning as training proceeds.

Dataset and Validity Notes

Current experiments use Simple Wikipedia passages converted into compact passage-level examples. The design goal is to hold semantics roughly constant while letting output length vary.

  • Training source: Simple Wikipedia passages preprocessed into JSONL records.
  • Unit of supervision: preference pairs between two candidate summaries of the same passage.
  • Validity concern: semantic overlap metrics can overestimate quality when two weak candidates share surface vocabulary.
  • Leakage concern to track in final write-up: avoid evaluating on passages or templates that appear in preference construction.

Evaluation Plan

Preliminary evaluation from the current run indicates stable optimization throughput, but generation quality is still mixed. The intended benchmark remains whether outputs can be shortened without semantic collapse.

  • Primary metrics: output length, semantic score, and pairwise preference accuracy.
  • Baselines: reference GPT-2 behavior without length pressure and ablations removing listener or decay schedule.
  • Interpretation rule: shorter is only meaningful if semantic retention stays competitive.
  • Current status: first epoch run finished (kept 8,726 pairs; skipped 18,274); sweep comparisons pending.

Results

We now have first-run evidence from March 7, 2026. These are tentative conclusions from one completed epoch and will be finalized after sweep comparisons.

Preliminary run available

Finding 1: Brevity vs Fidelity

The run shows partial brevity gains, but fidelity is inconsistent. Some generations avoid hard collapse and keep a few key entities, yet remain semantically noisy and lexically unstable.

Finding 2: Listener Value

Listener-based filtering is active and selective: 8,726 pairs kept vs 18,274 skipped in epoch 1 (about 32.3% kept), indicating many candidate pairs are rejected as low-value or too similar.

Finding 3: Emergent Telegraphic Style

Telegraphic compression appears intermittently, but collapse remains: earlier runs over-produced punctuation (for example "." at roughly 0.7-0.8 probability), while this run shows strong "kh/k" token dominance on one probe. The failure mode shifted rather than disappearing.

How to Read the Results

A lower output length by itself is not success. We will treat improvements as meaningful only when three conditions hold:

  • The shorter candidate keeps high semantic alignment with the source.
  • The behavior is consistent across passages rather than isolated examples.
  • The effect survives ablations removing the listener or the decay schedule.

Limitations and Failure Modes

  • Shorter outputs may arise from generic truncation instead of genuinely child-like content selection.
  • Token-collapse behavior persists across runs (earlier punctuation loops, current probe-specific lexical collapse), indicating decoding/training instability.
  • BERTScore-style signals do not fully capture pragmatic success or grammaticality.
  • Simple Wikipedia is cleaner and more adult-like than real caregiver-child interaction.
  • The current setup does not model turn-taking, grounding, or developmental progression over time.

Iteration and Next Steps

  • Early phase: establish the speaker-listener preference pipeline and stable DPO training.
  • Current phase: run sweeps over decay strength, preference filtering, and decoding settings.

Takeaway

Tentative conclusion: the objective is trainable and can produce occasional compressed keyword-style outputs, but this run does not yet show stable telegraphic quality. The next decision point is sweep analysis: we need better tradeoffs between brevity and semantic stability before making a stronger acquisition-style claim.
